# AI Collaboration Reflection

I used GitHub Copilot throughout the development of the football league table application as an AI coding assistant and brainstorming tool. I used it to discuss possible approaches to the problem, think through the structure of the application, generate implementation suggestions, and review parts of the code. I did not treat the suggestions as automatically correct. I reviewed them against the assessment requirements and made the final decisions about what was implemented.

One of the most useful interactions occurred when I was brainstorming how the league points should be calculated. GitHub Copilot initially suggested using the modern football scoring system of three points for a win, one point for a draw, and zero points for a loss. I disagreed with this suggestion because the assessment specifically requires the rules used by the English First Division during the 1974/75 season. The scoring system for that season awarded two points for a win, one point for a draw, and zero points for a loss. I therefore rejected Copilot's initial suggestion and implemented the two-points-for-a-win system instead. This was a good example of why I needed to validate AI-generated suggestions against the actual requirements rather than assuming that a technically common approach was appropriate for the problem.

Another area where I used Copilot was when considering the goal average calculation. The application needs to compare teams using their goal average, including the case where a team has conceded zero goals. Copilot provided suggestions for handling this edge case, but I reviewed the behaviour and adjusted the implementation so that a team that has conceded zero goals is represented with an unbounded/infinite goal average. This also required me to think about how that value would affect the sorting of the league table.

I also used Copilot to help me think about code organisation and implementation details. The application is divided into `Match`, `TeamStats`, `LeagueTable`, and `StandingsCalculator`, with each class having a specific responsibility. When Copilot suggested code that could be made clearer or simpler, I reviewed and refactored it where necessary. Readability is important to me, so I avoided keeping code simply because it was generated by the AI. I wanted the final implementation to be code that I could understand, explain, debug, and maintain myself.

The main lesson I took from this collaboration is that AI coding assistants are useful for exploring solutions and identifying implementation possibilities, but they do not replace understanding the requirements. An AI assistant can produce a plausible solution that is nevertheless incorrect for the specific problem. In this assessment, the incorrect suggestion about three points for a win demonstrated this clearly. I therefore treated GitHub Copilot as a development assistant and second pair of eyes while retaining responsibility for the technical decisions and the final implementation.
